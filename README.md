# hi-story

**你的故事写到了哪？**

hi-story 是一款以中世纪剑与魔法世界为背景的像素风角色扮演游戏项目，融合肉鸽的随机性、DND 风格的骰子检定与 CRPG 的角色扮演和自由选择。

玩家在迷雾中探索随机地图，遇见人物、事件与其他旅人，通过选择改变自己的经历。你可以追寻最终目标，也可以停在某个地方种地、酿酒、经营酒吧。每位玩家的旅程，最终都会被编成一段属于自己的故事。

> 项目处于早期开发阶段。以下内容包括设计方向和最终愿景，不代表所有系统已经实现。当前 main 分支以项目介绍为主。

## 核心体验

- **迷雾探索**：在探索中逐步认识世界，发现地点、人物、线索与事件。
- **随机迷宫与事件**：不同旅程拥有不同的遭遇，地图、NPC、伙伴与任务随故事生成。
- **自由选择**：尽可能提供丰富的选项，让玩家决定如何回应事件、与谁同行、在哪里停留。
- **动态故事**：玩家做出选择后，故事生成器调整后续路径，使世界继续回应已经发生的变化。
- **一段相遇**：玩家之间可以短暂同行、共同完成任务，也可能因为阵营冲突成为敌人。
- **自由生活**：冒险之外，也可以浇花、种地、酿酒，邀请旅人来到自己的菜园或酒吧。

## 随机故事与个人目标

每位玩家拥有自己的最终目标，目标池希望尽可能丰富。随机故事生成器以目标为方向，生成初始故事路径，并根据玩家的选择和关联状态的变化持续调整后续发展。

故事生成的内容包括玩家背景、NPC 背景、地点特点、任务、随机事件和可回应的选项。NPC 的故事可以围绕时间、人物、地点、个性、身上的事件及其回应展开；地图生成器再根据故事提供的参数生成地图。

玩家不必始终沿着目标前进。支线、偶遇和停留都可以成为这段经历的一部分。

### 性格系统

游戏中的选项要尽可能多。系统根据玩家实际做出的选择，反推玩家在**本次世界中的性格**，让角色的性格随着这段旅程逐渐显现。

## 多人世界的最终愿景

### 位面与切片

每位玩家在开始游戏时被送到不同的位面。设计设想将这些位面视为不同的数据世界（不同 db / 切片）。

玩家可以邀请朋友加入同一切片；加入新切片后，朋友将从原切片中消失。这是当前的世界设定，具体的数据隔离与迁移方式仍需在多人开发阶段细化。

### 相遇与分流

随机故事会在某个时期引导玩家相遇，也会在最终任务之前，将玩家引向不同的小支线。即使拥有相同的最终目标，也希望避免玩家在途中过早绑定最终的伙伴。

**玩家之间的状态，希望停留在“一段相遇”。**

眼前的陌生人可以成为这段路上的同伴，是否同行由玩家自己决定。当阵营冲突时，玩家也可能在那个时期成为敌人。

### 人数与任务

- 随机地图中的相遇以 **3—5 人**聚集为设想。
- 随机任务随当前任务中的玩家数量调整难度。
- 最终的胜利**可能需要 20 人**共同参与。
- 如果条件允许，希望地图尽可能庞大、任务尽可能丰富。
- 玩家标记参与相遇分配，例如“故事型”“速通哥”；不同标记类型的玩家会有更大的概率被分配到一起。

这些人数是最终体验的设计设想，具体容量与匹配规则需要在后续开发中验证。

## 战斗方向

战斗暂定采用战棋形式，以基础属性和骰子共同决定行动结果：

- 移动：基础移动能力结合骰子。
- 攻击：基础攻击能力结合骰子。
- 检定：基础成功几率结合骰子。

前期从生命、属性、状态、命中、伤害、回合、移动、攻击和胜负等最小机制开始，逐步丰富规则。

## 生活经营

玩家可以停留在某个地方，浇花、种地、酿酒，经营自己的菜园或酒吧，把路过的旅人邀请进来。

这部分的设想是在冒险世界里“嵌一个星露谷”：让停留和生活也成为完整的游戏体验。玩家可以选择为最终目标努力，也可以在途中建立自己的日常。

## 旅程成为故事

每位玩家的经历，最终都会被编成一段故事。追寻目标、结识旅人、遭遇冲突，或留在某处经营生活，都属于这段个人经历。

## 前期开发范围

前期先做**单人、有界地图的网页版 Demo**，优先打通探索、交互、选择、任务进度和最小战斗的玩法闭环，并完成稳定性验证，再逐步扩展内容。

多人位面、动态相遇、大规模最终任务和完整生活经营属于后续愿景，逐步推进。

当前开发按以下职责组织，具体实现和接口以对应模块说明为准：

| 模块 | 主要职责 |
| --- | --- |
| 生命周期与应用编排 | 初始化顺序、命令校验、跨模块提交、本局状态与重新开始 |
| 运行器 | 移动、碰撞、迷雾、交互距离、地点触发，以及人物状态、骰子检定和最小战斗 |
| 事物模块 | 任务与物品接入、资源和线索变化、事件装配与执行、避免重复结算 |
| 随机故事生成器 | 背景、故事路径、NPC 事件、任务和选项生成，以及关联变化后的后续更新 |
| 随机地图生成器 | 根据故事提供的地点与地貌等参数生成有界地图 |
| 随机人物生成器 | 根据随机参数或传入的角色参数，装配人物外观 |

各模块通过明确的参数和接口协作，降低耦合。决定性的改动应同步更新对应模块说明，便于不同开发会话保持一致。

## 开发原则

- 先完成小规模、可验证的玩法闭环，再扩展内容与系统规模。
- 明确区分已实现功能、当前开发范围与最终愿景。
- 随机内容需要回应玩家已经做出的选择，保持故事和世界状态连贯。
- 故事、地图、人物生成与运行执行分工明确，便于持续迭代。
- 细节边做边丰富，让每次旅程逐渐拥有更多可能。
