# 场景卡顿修复验收

开发分支：codex/fix-scene-freeze，继承0357269。产品仍为0.4.0，领域snapshot0.2.1/schema4/save1；既有进度直接恢复。本次只修改表现层，不重新开发或合并其他模块的新功能。

## 复现与修复

在1440×1000和375×812的真实Chromium中，使用CDP模拟4倍CPU减速。旧版桌面在加载后仍反复出现约150—250ms长任务；不是纯粹等待网络。逐项隔离确认大量重复Canvas图像合成是主要持续负载，关闭CSS滤镜未消除问题。初次素材处理也有秒级任务，不能把加载前耗时归为稳定运行帧率。

- 景物、裁切和阴影缓存为静态层，屏幕只绘制其可见部分。
- 人物、地标、关闭通路和淡出遮挡区域局部清除缓存，再按原深度重绘地表/景物/演员；避免半透明景物重复叠加。
- 等素材加载完成再建立地表，避免先后重建两遍。静止SVG不重复写属性，后台页不绘制，空闲与慢设备主动让出主线程。
- 人物中心、自动靠近、战术操作及存档协议保留。

## 实际验证

类型、边界、构建和diff检查通过。以下为两个独立批次，未重跑320项领域逻辑：

1. player-camera.spec.ts和v040.spec.ts：桌面/375px共10项通过，0跳过/重试。覆盖连续/触摸/自动移动、每帧人物中心、拖动/缩放/屏幕变化、战术移动与退出、NPC检定/复看不重复结算和刷新。
2. scene-responsiveness.spec.ts：真实时间、4倍CPU减速、单worker，桌面/375px共2项通过，0跳过/重试。稳定段主画布每帧24次图像调用；50ms定时器的最大实际间隔桌面141.2ms、窄屏82.6ms。真实按键移动、松开停止、背包/旅程点击及存档刷新均通过，pageerror为空。

测试机器、软件绘制和CPU减速影响数值；这些结果不等于所有用户设备的帧率保证，也不包含完整冒险整局重测。冷启动人物素材仍需一次合成；本轮解决持续重复绘制造成的主线程占满。
