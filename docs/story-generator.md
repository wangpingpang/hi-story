# 随机故事生成器 v0.3

入口：`/?view=story-generator`。不调用 AI API，运行时不联网。

## 已实现

- 有种子的本地随机组合：4类冲突、4区域、5背景、8姓名、6身份、6个性；每局3个 NPC，生成后保持身份不变。
- 每局1条主线、1条支线。初始18个选项；行动按对象和世界条件生成，随条件失效撤销。
- NPC调用带参人物接口补齐完整资料，保存身份、个性、地点、目标、事件、回应、线索、存活与信任；世界时间和日志提供事件时间。
- 初始化、玩家行动、外部世界变更三个公开入口。行动含版本检查，结果编号去重；处理过程使用工作副本，非法输入不污染原状态。
- 变化后使用字段依赖索引调度受影响的任务反应，选项仍按实时条件生成；关联计划按读取字段重算。反应规则可有限级联，每个对象每个事务只执行一次。
- 死亡终止原委托和互动，其他知情者与既存笔记提供有依据的替代路径；全部线索丢失进入失败终局。
- 支线成功、失败、放弃、过期；主线成功、失败、主动退出。已终止任务保留结果，后续资源损失不会改写过去完成事实。
- 旧工坊保留region/tags/npcIds需求摘要和战斗结果模拟。新集成Demo通过createStoryMapRequest输出完整几何请求，由地图生成器和运行器执行真实探索及战斗。
- 类型、应用与展示分离，原雾桥剧情和人物工坊保留。
- 行动与任务结算规则已迁移为 JSON 包，支持运行时注册、替换和卸载扩展；详见[规则包契约](story-rule-packs.md)。

## 接口

`initializeStory(seed, background?)` 返回世界。背景含展示文本与标签。

`storyOptions(world)` 按实时条件返回行动。

`processPlayerAction(world, { id, revision, optionId })` 返回新世界或待结算战斗请求。

`receiveWorldChange(world, resultId, change)` 接受人物死亡、时间、地点通行、物资、笔记变化，返回新世界。外部集成负责验证结果真实性、关联战斗请求并处理网络权限。

2026-10-14新增`createStoryMapRequest(world)`以及`player-location`、`player-defeat`事实。新`/?view=demo`由生命周期确认实际坐标、战斗结果并协调物资/任务投影；完整边界见根目录《随机故事生成器说明.md》。

## 本版边界

这是可运行的规则原型。四类冲突有明确结局，但尚未实现任意目标自动规划、完整事件链规划、独立NPC计划、认知/事实隔离、历史加权抽样、复杂技能骰检定、多人或存档导入校验。背景文字和标签目前保存展示，尚未影响规则选择；个性用于描述，信任用于反馈，尚未影响所有行动概率。地图生成已接入新Demo，当前为三地区模板；尚未动态扩展空间或重生NPC。

任一**受支持状态**变化都会重检；NPC迁移、关系网、物品所有权等需要后续增加对应变更契约和规则。禁止外部直接修改内部对象，应通过上述入口提交变化。

新增四阶段任务图和候选路线重算；关联变化沿反应依赖继续传播。人物/任务作用域与集合引用均参与索引，详见[阶段任务说明](story-stage-planning.md)。

## 验证

原故事测试包括100种子路径检查、死亡、线索消失、到期、幂等、通行变化、拒绝与完成、版本失效、战斗边界；规则包与阶段测试保持回归。此前111项逻辑及原工坊浏览器验收为历史结果，本轮全项目145项逻辑测试通过；新增Demo浏览器用例尚未执行。见demo-integration-report.md。
