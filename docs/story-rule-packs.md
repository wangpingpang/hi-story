# 故事规则包与运行时装卸 v0.2

本次将故事业务分支迁出 TypeScript 核心，改为经过校验的 JSON 规则包。入口仍为 `/?view=story-generator`。普通剧情新增通过规则包完成；引擎解释固定的条件与效果运算。

## 文件职责

| 文件 | 职责 |
|---|---|
| `content/story/core-rules.json` | 原有18个初始选项及任务成功、死亡、过期和终局规则 |
| `content/story/camp-rules.json` | 可装卸样例：营地休整、篝火线索、信任反馈 |
| `model.ts` / `initialize.ts` / `random.ts` | 世界类型、开局装配、有种子随机数 |
| `rule-types.ts` / `schema.ts` | 规则语言类型及 JSON 数据校验 |
| `registry.ts` | 注册、替换、卸载、依赖检查、编号检查、版本管理 |
| `fields.ts` | 可读写字段和文字模板；按任务ID查找任务，避免依赖数组顺序 |
| `interpreter.ts` | 通用条件求值、效果执行、集合遍历和执行预算 |
| `engine.ts` | 选项绑定、命令校验、事务结算、反应传播、外部结果适配 |
| `src/application/story-studio.ts` | 协调世界与注册表，原子发布配置变更，管理待结算战斗 |

## 规则包契约

```json
{
  "schemaVersion": 1,
  "id": "pilgrim",
  "version": "1.0.0",
  "name": "旅人援助",
  "requires": ["core"],
  "actions": [{
    "id": "pilgrim/donate",
    "scope": "world",
    "category": "援助",
    "text": "捐出1金币帮助旅人",
    "cost": 1,
    "when": {
      "op": "gte",
      "left": {"ref": "gold"},
      "right": 1
    },
    "effects": [{"op": "add", "path": "gold", "value": -1}]
  }],
  "reactions": []
}
```

把这份 JSON 导入页面，捐助选项立即出现。卸载后选项消失，已经花掉的金币和日志保留。同一编号可经应用层 `replace()` 换版本；页面导入默认执行注册，重复编号会拒绝，避免静默覆盖。

`scope` 为 `world`、`npc`、`quest`。NPC或任务行动按对象展开，选项编号追加对象ID，如 `ask:npc-0`。行动编号在已加载的包之间必须唯一，建议使用包名前缀。每个包内的反应编号唯一，不同包的反应使用包名隔离。

`requires` 是依赖的包ID；当前不解释语义版本范围。`version` 用于标识素材版本，`schemaVersion` 控制规则语言兼容性。

## 条件、效果与字段

| 类别 | 支持的运算 |
|---|---|
| 条件 | all、any、not、eq、ne、gt、gte、includes、some |
| 效果 | set、add、format、text、when、chance、each |
| 作用对象 | 世界、NPC、任务 |
| 模板 | `{npc.name}`、`{conflict.need}`、`{goal}` 等已登记字段 |
| 外部请求 | NPC作用域的 combat；发送请求时不执行即时效果 |

字段经白名单登记：金币、线索、物资、笔记、通行、终局，NPC存活/信任/回应，以及任务状态和原因。时间只读，行动以 `cost` 推进时间，外部时间变化经过专用入口。身份、姓名、知识等可用于条件与模板，不允许规则包直接改写。

新剧情可组合现有运算。新的底层能力，例如技能骰检定、物品转移或新领域字段，需要增加相应的宿主运算或适配器；当前不提供任意 JavaScript/TypeScript 代码插件执行。

## 运行与装卸

应用层持有独立 `RuleRegistry`，不同局实例的扩展配置不会互相污染。

1. 注册前解析和校验整个包，并检查编号、依赖和作用域。
2. 注册表保存冻结快照，源对象后续修改不会影响当前规则。
3. 每次生成选项，从注册表读取规则，按条件绑定NPC/任务对象。
4. 玩家行动同时校验世界版本和规则版本，结算在世界副本中进行。
5. 应用状态效果后扫描反应，反应产生的变化可启用下一条反应。
6. 每个“包＋反应＋对象”每个事务最多执行一次；全部求值和执行受预算限制。
7. 成功后发布新世界；失败则不提交副本。

运行时配置变更采用“注册表副本＋世界副本”，完成规则校验、反应执行和选项查询后一起提交。任何一步失败，当前配置与世界都保留。

- `install(input)`：安装 JSON 字符串或数据对象。
- `replace(input)`：替换同ID扩展包，旧版本命令失效。
- `uninstall(id)`：卸载扩展包；被其他包依赖时拒绝。
- 基础 `core` 包不可运行时卸载或替换，承担当前主支线闭环契约。
- 待结算战斗期间，应用层暂停其他行动和装卸；结算目标结果与时间后解除暂停。
- 世界日志与状态效果保留；已结束任务和已产生的终局不允许规则包改写。
- 重新开局保留当前扩展配置，重置世界并应用已加载反应；刷新页面恢复默认配置。本版尚无持久存档。

v0.3已将反应调度改为字段依赖索引，并新增可选 plans 阶段图；参见[阶段任务与依赖更新](story-stage-planning.md)。选项仍实时计算。

## 执行边界

包上限256000字符、单数组64项、最多32包、嵌套深度16，每次解释预算20000步。非法路径、未知运算、错误作用域、字段类型错误和数值溢出会拒绝。包不修改历史数组，不执行字符串代码，不加载远程脚本。

插件可写字段属于当前世界模型。独立插件状态命名空间、任意目标的自动规划、模块代码的运行时加载、多人服务端授权和存档恢复仍未实现。完整复现需保留相同引擎版本、规则包内容、装卸顺序、种子和行动序列；当前日志记录包ID和版本，不存整份规则包正文。

## 测试

逻辑测试覆盖原故事闭环及注册、卸载、替换、依赖冲突、版本失效、源对象修改隔离、加载与行动失败回滚、反应传播、任务终局保护、战斗待结算及执行预算。浏览器测试覆盖桌面和手机的加载、使用、JSON导入、卸载和非法包反馈，同时回归原雾桥与人物工坊。

验收结果：90项逻辑测试通过；14项桌面/手机浏览器回归通过，最终故事页面调整后4项重点复测通过。类型检查、领域边界检查、生产构建通过。证据位于 docs/evidence/story-rules-logic-results.json、story-rules-browser-results.json、story-rules-browser-final.json。
